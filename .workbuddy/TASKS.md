# 后续迭代任务（可交给 WorkBuddy）

## 已定义的迭代要求

- [ ] 每一款官方 MCP 实时商品都能从网页打开**家庭做法参考**或明确的「配方未知/组合餐请拆分」指引。
- [ ] 区分完整社区原创食谱、品类烹饪参考和无充分信息的餐品。禁止虚构官方商业配方。
- [ ] 为常见品类建立独立烹饪方法：汉堡、鸡块、鱼、薯条、鸡翅、早餐、卷饼、甜点、咖啡/饮料等。
- [ ] 套餐类显示「逐个查看构成」以及适用的家庭做法模板，不得将套餐视为单一成分。
- [ ] 对每种模板至少标注建议食材、基本步骤、时间、设备与过敏原/食品安全（能可靠确定时）。
- [ ] 在真实官方菜单的浏览器 E2E 中验证**所有渲染商品均有指南入口**，不得触发下单支付。
- [ ] 使用真实厨房测试结果逐项把「品类参考」升级为结构化 Rust 社区完整食谱。

## 不能做的事

- 不能为了「全覆盖」而将自动生成的猜测标记为官方配方或经过实测；
- 不导出或公开受保护的用户地址、Token、订单详情；
- 不创建虚假 WorkBuddy 会话记录、运行轨迹、成果证明。

## 使用方式

打开 WorkBuddy → 选择本仓库为工作目录 → 参考 `.codebuddy/CODEBUDDY.md` 与本文件 → 逐项实现、复核与运行测试 → 经代码审查后合并。
